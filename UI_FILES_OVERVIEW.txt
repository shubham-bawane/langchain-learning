🔗 API ENDPOINTS REFERENCE
═══════════════════════════════════════════════════════════════════════════════

1. Create Session
   POST /api/session/create
   Response: { "session_id": "uuid-string" }

2. Send Chat Message
   POST /api/chat/message
   Body: { "session_id": "...", "message": "..." }
   Response: { "success": true, "response": "...", "state": {...} }

3. Get Preview HTML
   GET /api/preview/html?session_id=...
   Response: { "html": "<html>...</html>", "framework": "Tailwind" }

4. Download HTML
   GET /api/download/html?session_id=...
   Response: (Binary file download)

5. Get Message History
   GET /api/session/<session_id>/messages
   Response: { "messages": [...] }

6. Health Check
   GET /api/health
   Response: { "status": "healthy", "active_sessions": N }

7. Serve UI
   GET /
   Response: index.html (rendered)

📋 PRODUCTION DEPLOYMENT CHECKLIST
═══════════════════════════════════════════════════════════════════════════════

Before deploying to production:

  ☐ Set FLASK_ENV=production
  ☐ Add HTTPS/TLS certificates
  ☐ Implement user authentication
  ☐ Add rate limiting (10-20 requests/min per IP)
  ☐ Enable CSRF protection
  ☐ Add Content Security Policy headers
  ☐ Switch from Flask dev server to Gunicorn
  ☐ Use reverse proxy (nginx) for load balancing
  ☐ Setup Redis for session persistence
  ☐ Configure monitoring and logging
  ☐ Add error tracking (Sentry)
  ☐ Implement health checks
  ☐ Setup backup and recovery
  ☐ Test with security scanner
  ☐ Document deployment process

Recommended Production Stack:
  • nginx (reverse proxy)
  • Gunicorn (4-8 workers)
  • Flask (Python backend)
  • Redis (session cache)
  • PostgreSQL (data storage)
  • Qdrant (vector database)
